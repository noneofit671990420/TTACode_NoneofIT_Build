# BONSAI-GERONIMO-BRANC — desk-side bring-up instructions for Command Code

> **Secrets are not in this file.** The PSK and ntfy topic names were
> generated by Juno and live in her `config.json`. Get the real values
> from the human (or Juno) directly — never commit `config.json` to git.
> The repo's root `.gitignore` already excludes it.

## Mission

Stand up the desk end of a bidirectional text link to Juno (the AI).
Two transports, both live, automatic failover in both directions:

1. **direct** (primary) — you listen on TLS; Juno connects out to you.
2. **ntfy** (fallback) — public relay, no firewall changes needed.

Plus a **host frontend**: a small browser chat UI for the human sitting
at the desk. Every message is HMAC-SHA256 authenticated — flip one bit
after authentication and it's dropped on arrival.

## Files

- `wire.py` — the protocol. Do not modify; it must stay byte-identical
  in behavior to Juno's copy.
- `desk_link.py` — your daemon + host frontend. Stdlib only, Python 3.8+.
- `config.json` — **you write this** (template below). Never commit it.
- `config.example.json` — template, safe to keep.

## Step 1 — secrets and config

Write `config.json` exactly like this. The `psk_hex` and the two ntfy
topic names **must match Juno's side byte-for-byte** — paste the real
values you received from the human:

```json
{
  "psk": "<64-hex-char PSK from Juno>",
  "ntfy_base": "https://ntfy.sh",
  "ntfy_inbox": "<secret>-inbox   (desk -> juno; fixed labels on both ends)",
  "ntfy_outbox": "<secret>-outbox  (juno -> desk; fixed labels on both ends)",
  "direct_port": 17431,
  "tls_certfile": "desk.crt",
  "tls_keyfile": "desk.key"
}
```

Key names must match exactly: `psk` (not `psk_hex`). The `psk` value and
the two ntfy topic names **must match Juno's side byte-for-byte** — paste
the real values you received from the human.

## Step 2 — certificate

In `skills\desk-link\`, generate the desk's self-signed TLS cert:

```powershell
openssl req -x509 -newkey rsa:2048 -keyout desk.key -out desk.crt `
  -days 825 -nodes -subj "/CN=desk-link"
```

(Windows: Git for Windows ships `openssl.exe`.)

## Step 3 — open the gate

Port-forward TCP **17431** on the router to this PC. Then send Juno:

1. Your public IP address or hostname
2. The direct port (17431 unless you changed it)
3. The full `desk.crt` PEM text (the `.crt` file, not the key)

Juno pins that certificate; without it she cannot connect.

## Step 4 — run it

```powershell
python desk_link.py
```

Optional: `--config other.json`, `--frontend-port 17432`.

## Step 5 — the host frontend (for the human)

Open in the desk's browser:

```
http://127.0.0.1:17432/
```

You get a chat view, a send box, and two status dots:

- **direct** — the TLS socket Juno dials into (primary)
- **ntfy** — the public relay fallback

Green dot = live and recently verified (a real frame arrived, not just
a socket open). If one path dies, traffic fails over to the other
automatically; when it recovers, the link fails back to direct.

The frontend binds **127.0.0.1 only** — it is reachable from the desk
itself, never from the network. That is deliberate.

## Driving it from Command Code

The daemon still speaks the original machine bus:

- **outbound** (desk → Juno): write a plain-text line on the daemon's
  stdin, it goes out over the best transport.
- **inbound** (Juno → desk): each frame prints on stdout as

  ```
  DESKLINK-CHAT {"from": "...", "text": "..."}
  ```

Text pipe only, never a shell. Inbound text is never executed; actions
stay behind human approval.

## Sanity checks

1. Frontend loads at `http://127.0.0.1:17432/` and both dots appear.
2. Type in the frontend → the line also appears on the Command Code
   stdout bus as `DESKLINK-CHAT`.
3. Juno sends a test line → it appears in the frontend chat and on
   stdout. Reply from the frontend; she should see it.
4. Kill the direct path (block the port / stop forwarding) → ntfy dot
   stays green, chat keeps working. Restore → fails back to direct.

Report back: public IP/hostname, port, and `desk.crt` so Juno can aim
the direct socket at you. The channel is **not live** until the
real-network checks above pass in both directions.
